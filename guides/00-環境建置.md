# 懶人包 #00：環境建置

> 版本：v1.0（合併版）
> 更新日期：2026-08-02
> 適用：Claude Code / Codex / OpenCode / Antigravity

> 📌 **本懶人包可獨立執行**：會自動檢查並安裝所需工具，不需要先看過其他懶人包。

---

## 這份懶人包會幫你做什麼？

- 確認你的 AI Agent 本體已安裝並登入
- 安裝 **Node.js LTS**（很多 MCP server 用它執行）
- 安裝 **uv**（Python 工具管理器，後續 MCP 工具會用到）
- 驗證所有工具都能正常使用

> 💡 **本懶人包只負責基礎工具。**
> Git、GitHub CLI、GitHub 帳號登入全部由 **#02：連接 GitHub** 負責。
> 本流程**不檢查 GitHub 帳號、不執行 `gh auth status`、不安裝 Git 或 GitHub CLI**。

---

## 先備條件

- [ ] 已有對應的 AI 服務帳號（見下方「依你的 Agent」）
- [ ] 電腦有網路連線

---

## 完成標準

- [ ] AI Agent 本體能開啟並正常對話（已登入）
- [ ] `node --version` 是仍受官方支援的 LTS
- [ ] `uv --version` 有正常版本輸出
- [ ] 全程沒有要求 GitHub 帳號或 GitHub 登入

---

## 執行原則（給 AI Agent）

一次只做一個步驟，完成後再繼續。並且：

- **每次安裝前先顯示將執行的命令並取得使用者確認。**
- **已安裝且版本正常的工具直接跳過**，不要一開始就重裝所有東西。
- 先辨識作業系統，再選對應命令。**不可跨 PowerShell、CMD 與 Bash 混用命令。**
- 同一個工具不要同時混用多種安裝來源（winget / Scoop / Chocolatey / npm 擇一）。
- 安裝後若目前程序仍找不到指令，**先重開終端機或 agent 再檢查**，不要立刻判定安裝失敗。

---

## 步驟零：環境檢查

> 開始前先自動確認以下項目，把缺少的記錄下來，後續步驟逐一安裝。
> **不要跳過任何一項，不要假設環境正常。**

1. **確認作業系統**（Windows / macOS / Linux）—— 後續指令依實際系統選擇正確版本
2. **確認網路連線正常**
3. **檢查 Node.js**：`node --version`、`npm --version`
4. **檢查 uv**：`uv --version`
5. **檢查 agent 本體**（見「依你的 Agent」，指令各不相同）

逐一執行，避免某一個失敗後看不到其餘結果。

> ⚠️ **Node.js 必須是仍受官方支援的 LTS。**
> 不要只用「主版本大於 18」判斷 —— 舊的大版本可能已經停止支援。
> 版本狀態見 https://nodejs.org/en/about/previous-releases

> 告知使用者目前狀態，例如：「uv 未安裝 ❌，接下來會幫你安裝。」

---

## 步驟一：安裝你的 AI Agent 本體

各 agent 的安裝與登入方式不同，見文末「[依你的 Agent](#依你的-agent)」。
已經在用該 agent 執行這份懶人包的話，這一步通常已經完成，確認登入狀態即可。

---

## 步驟二：安裝 Node.js LTS

> 未安裝、已停止支援、或不是 LTS 時才需要執行。

**Windows（PowerShell）**

```powershell
winget install --id OpenJS.NodeJS.LTS --exact --accept-source-agreements --accept-package-agreements
```

**macOS**

```bash
brew install node
```

**Linux（Ubuntu / Debian）**

依 Node.js 官方建議方式安裝**目前的 LTS**，不要把版本寫死在過期的大版本：

```bash
curl -fsSL https://deb.nodesource.com/setup_lts.x | sudo -E bash -
sudo apt install -y nodejs
```

安裝後重開終端機並確認：

```bash
node --version
npm --version
```

---

## 步驟三：安裝 uv

**Windows（PowerShell）**

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

**macOS / Linux**

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

重開終端機後確認：

```bash
uv --version
```

> 如果 `uv` 指令找不到，關閉所有終端機視窗重新開啟再試。

---

## 步驟四：最終驗證

```bash
node --version
uv --version
```

再加上你的 agent 本體檢查（見下表），並確認 agent 顯示已登入、可正常對話。

> 全部通過後告知使用者：
> 「✅ 環境建置完成！你的電腦已經準備好使用所有懶人包了。」

## 依你的 Agent

| Agent | 本體安裝 | 登入 | 檢查指令 |
|---|---|---|---|
| **Claude Code** | 桌面版（Pro 方案以上） | 開啟桌面版即為已登入 | 能在 Code 分頁正常對話 |
| **Codex** | [官方下載頁](https://developers.openai.com/codex/app) 的 Desktop app | Sign in with ChatGPT（建議）或 API Key | Desktop 能對話；CLI 選用時 `codex --version` |
| **OpenCode** | `npm install -g opencode-ai` | `opencode auth login` | `opencode --version`、`opencode auth list` |
| **Antigravity** | IDE 本體 | IDE 內建帳號登入 | IDE 能正常對話 |

### Claude Code

所有安裝與設定都可在桌面版的 Code 分頁內完成，**不需要另外打開 PowerShell**。
只有桌面版確實無法執行某個指令時，才引導使用者到終端機。進階使用者也可直接用 CLI 版本。

### Codex

- 到 [官方下載頁](https://developers.openai.com/codex/app) 取得 macOS（Intel / Apple Silicon）或 Windows 安裝檔
- 開啟後選 **Sign in with ChatGPT**（OAuth 自動處理，Plus/Pro 等訂閱會自動生效），
  或 Sign in with API Key（貼 `sk-...` 開頭的 OpenAI API Key）
- Windows 也可用 `winget install Codex -s msstore`
- **Linux 沒有 Desktop app** → 改用 IDE 擴充（VSCode / Cursor / Windsurf 搜「ChatGPT」OpenAI 官方）
  或 CLI（`npm install -g @openai/codex`）。三者設定共用，後面所有懶人包都通用
- **缺少選用的 Codex CLI 不算環境建置失敗**，使用 Desktop app 的人可直接繼續

### OpenCode

```bash
npm install -g opencode-ai
opencode --version
```

Windows 也可使用官方文件列出的 Scoop 或 Chocolatey，但**不要同時混用多種安裝來源**。
Windows 原生環境可以用，但 OpenCode 官方建議需要最佳相容性時使用 WSL。

模型供應商設定：

```bash
opencode auth list
```

尚未登入任何供應商時，請使用者**在互動式終端**執行 `opencode auth login`
（agent 代跑會卡在等待輸入）。登入後可用 `opencode models` 確認。

### Antigravity

IDE 本體與登入由 IDE 自己處理，本懶人包不介入。Node.js 與 uv 仍需安裝，
因為後續的 MCP server 會用到。

## 如果失敗，如何重來

對你的 agent 說：

> 「環境建置懶人包執行失敗了，幫我檢查哪裡出問題，重新處理。」

Agent 會重跑步驟零的檢查 → 找出失敗項目 → 只針對失敗項目重新安裝。

## 常見問題

| 問題 | 解法 |
|------|------|
| `winget` 指令找不到 | Windows 10 1809 以上才內建；或到 Microsoft Store 安裝「App Installer」 |
| `brew` 指令找不到（macOS） | 先安裝 Homebrew：`/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"` |
| 安裝後指令仍找不到 | 關閉所有終端機視窗（或整個 agent），重新開啟後再試 |
| Node.js 版本太舊 | 安裝 `OpenJS.NodeJS.LTS`，完成後重開終端機再驗證 |
| 公司電腦裝不了 winget / brew | Codex Desktop 等 app 的安裝檔是 `.dmg` / `.exe`，不需套件管理器 |
| Desktop app 開不起來 | macOS：右鍵→開啟（首次繞過 Gatekeeper）；Windows：以系統管理員身分執行一次 |
| Sign in 卡住（Codex） | 改用 API Key 登入；或檢查瀏覽器是否封鎖 OAuth 跳轉 |
| Linux 沒有 Desktop app | 改用 IDE 擴充或 CLI |
